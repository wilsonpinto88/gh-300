⌨️What Copilot CLI is

💬

Terminal agent

Chat, plan and do coding tasks without leaving the shell.

📁

Files & commands

Reads, edits and runs files in a folder you trust.

🐙

GitHub built in

Ships with the GitHub MCP server: issues, PRs, repos.

🧑‍⚖️

Approval first

Asks before tools run unless you pre-approve them.

💡
Benefit for developers: less context switching. Ask, script and fix from the terminal, then hand bigger work to the cloud agent.

⚖️Interactive vs programmatic

Interactive: copilot

  • Conversation you steer
  • Shift+Tab cycles modes: ask/execute, plan, autopilot
  • Plan mode asks questions and builds a plan before code
  • Resume: /resume, --resume, --continue
VS

Programmatic: -p

  • One prompt, then exits
  • Scripts, CI, automation
  • Needs approval flags to edit or run
  • Can pipe options in: ./opts.sh | copilot

🔐Tool approval

--deny-toolalways wins over allow options
--allow-tool='shell(git)'one tool or command family
--allow-tool='write'file edits without asking
--allow-tool='SERVER(tool)'a specific MCP tool
--allow-all-tools / --yolosandbox only: same access as you
⚠️
Auto-approval lets Copilot run any command you could run. Use it only in an isolated environment. Deny rules and enterprise restrictions still apply.

🏢Organization-wide policies

🎚️

Feature policies

Enable or disable features per org: IDE chat, CLI, cloud agent, code review, MCP, models.

🏛️

Enterprise first

Enterprise owners can enforce a policy or let each org decide.

🌐

Everywhere

Policies apply across supported IDEs and github.com.

🚧

Content exclusions

Set at repo, org or enterprise level to hide paths from Copilot.

Copilot code review policies

Automatic reviews→From user settings or a ruleset. Not hierarchical: either turns it on, one review is posted
Re-review after pushes→Only with "Review new pushes", otherwise request it again manually
Required approvals→Copilot reviews do not count by default. Only when Copilot approvals are enabled
Unlicensed members→Can get reviews if the org enables code review without a Copilot license

📜Audit log events

💡
The audit log answers "who changed Copilot settings or seats, and when". Usage and adoption questions belong to the metrics API instead.

🔌Manage subscriptions with the REST API

EndpointDoes
GET /orgs/{org}/copilot/billingSeat breakdown and feature policies
GET /orgs/{org}/copilot/billing/seatsList seats, with last_activity_at
POST /orgs/{org}/copilot/billing/selected_usersAdd seats for users
DELETE /orgs/{org}/copilot/billing/selected_usersSet seats to pending cancellation
POST / DELETE …/billing/selected_teamsSame for whole teams
👑

Org owners only

Only organization owners can view and change seats.

🔑

Token scopes

Classic token: manage_billing:copilot, or read:org to read, admin:org to write.

⏳

Removal timing

Access ends at the end of the billing cycle, unless a team still grants it.

📈

Activity

last_activity_at needs IDE telemetry enabled.
